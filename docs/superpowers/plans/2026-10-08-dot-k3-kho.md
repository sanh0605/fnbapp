# Đợt K3 — các màn Kho mặc khuôn dùng chung (BR-UI-005), gộp đợt 8b

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Who does which task is fixed by `CLAUDE.md` ("Ai viết code"): screens (`.tsx` under `app/`) → Gemini via `agy`; guard test, screen tests written before the screen changes, docs, review → Opus; `lib/` (none planned) → Sonnet.

**Goal:** Every screen under Kho in the menu (Phiếu nhập, Phiếu xuất, Kiểm kê, Hàng hoá, Quy đổi, Đơn vị, Nhóm hàng, Nhà cung cấp, Tài sản, Thời hạn khấu hao) uses the K2 templates: no `type="number"` box, no hand-painted solid button, no hand-drawn `<table>`, no bold row cell, no hand-styled text box, select or `<h1>`. Phiếu nhập and Phiếu xuất also move onto the shared list and detail pieces (wave 8b of the master plan), and `IssueSlipDetailClient.tsx` (719 lines) is split.

**Architecture:** No new component and no server change. Each task removes its files from the guard's debt lists first (the guard goes red naming them), writes the screen tests for each number box that changes (red on the old `type="number"` box), then hands the screens to Gemini with a brief, then runs the tests and the type check. Number boxes keep the page's own state shape and convert at the boundary, so server actions, drafts and posted form values stay byte-identical.

**Tech Stack:** TypeScript, Next.js App Router, React 18, Tailwind, Vitest + Testing Library (jsdom).

**Spec:** `docs/superpowers/specs/2026-10-07-khuon-thanh-phan-design.md` (sections 2.1–2.6, 3, 4 row K3 and the 8b line, 5). Shared list/detail pieces: `docs/superpowers/specs/2026-10-02-khuon-danh-sach-chi-tiet-design.md` section 5. Rules: `BR-UI-001`, `BR-UI-003`, `BR-UI-005`, `BR-UI-008` in `docs/02-rules/business-rules/screens.md`; `BR-CASH-005`; `BR-DATA-007` (no popups).

## Global Constraints

- Templates (K2, `components/ui/`): `Button` (`primary` | `secondary` | `delete` | `danger`, `href`, className for layout only), `NumberInput`, `MoneyInput`, `TextInput`, `Select`, `Field`, `Table` set (`Table`, `TableHead`, `TableHeaderCell`, `TableBody`, `TableRow`, `TableCell`, `TableTotalRow`, `TotalCard`), `MoneySummary`, `list/DataList`, `list/ListPageHeader`, `list/FilterCard`, `list/ListPagination`, `detail/DetailHeader`, `detail/DetailFrame`, `detail/FieldList`, `detail/RemoveRecordButton`, `PageHeader`, `BackLink`, `Badge`, `DayInput`, `SaigonDateTimeInput`, `SearchableSelect`.
- A `NumberInput` inside a `Field`: give the hint and the error to `NumberInput`, not to `Field` (both would use the id `${id}-message`; K2 review minor).
- Copy (spec 2.2, verbatim): "Cần nhập số." · "Số lẻ dùng dấu chấm, ví dụ 1.5" · "Nhập số lớn hơn 0." · "Nhập số từ {min} trở lên." · "Nhập số không quá {max}." · placeholder "Ví dụ: …". A page's existing error sentence for a limit (e.g. stock headroom) is kept as `maxMessage`.
- All visible text Vietnamese; labels in sentence case except Topping, MR.PHIN, PO and units.
- No popups (`BR-DATA-007`); no new server action; posted form values identical to today (`150000`, `1250.5`).
- Every control 44px tall; desktop table plus phone cards for every list (`.claude/rules/ui-devices.md`); `inputMode` numeric/decimal comes from `NumberInput`.
- One brown main button visible per screen at any moment.
- Never delete a test; a test changed because a box is no longer `type="number"` (role `spinbutton` → `textbox`, typed value now grouped) says so in the commit.
- The guard's debt lists may only shrink: every file a task finishes leaves every list it was on.

### Task 8: Empty boxes show only a worked example; long names in pick lists shown whole (BR-UI-009, BR-UI-010, owner 2026-10-08 "a", "a")

Added the same day after Task 5. Changes existing screens and two templates, no new table or screen, so a short design here.

**Hiện trạng** (đã xem: `components/ui/NumberInput.tsx`, `TextInput.tsx`, `SearchableSelect.tsx`, every `placeholder=` under `app/` and `components/`, the prefilled `useState` values, `validatePurchaseOrderLine`. Chưa xem: POS boxes one by one, which only change wording.)
1. *States.* A box is empty (grey "Ví dụ: …"), typed, or showing a saved value. A new entry starts empty, except date/time boxes, which start at now / today (`BR-UI-009`, owner "a").
2. *Buttons.* None added. The pick list's open panel and its rows change look only.
3. *Lists.* Covered: every typed box under `app/` and `components/` (POS included, wording only). Left out: lists to pick from ("-- Chọn --", "Chọn mặt hàng..."), password boxes ("******", "Mật khẩu…"), date/time boxes, the sales-order edit's −/+ counter.
4. *Inputs.* Phiếu nhập "Số lượng" may now be left empty; completing with it empty or 0 is refused with "Vui lòng nhập số lượng" (today nothing stops it, because it always held 1). Asset disposal quantity starts empty; its existing "Cần nhập số." covers it. Every other box keeps its limits.
5. *Data.* Display only; nothing saved changes shape. A Phiếu nhập line saved with an empty quantity can no longer reach the server as 0 when completing; a draft may keep it empty, as a draft may keep any field empty.

Design:
- `TextInput` gains `example` → placeholder "Ví dụ: {example}". `NumberInput`/`MoneyInput` already do this.
- `SearchableSelect`: the search box inside the open list reads "Ví dụ: {first option's name}" (a real name from that list), "Gõ để tìm" when the list is empty; the box is labelled "Tìm trong danh sách" for screen readers and tests. Rows wrap (`whitespace-normal break-words`, no `truncate`); the open panel is at least as wide as the box and up to 28rem on a computer; the chosen name in the closed box is clamped to two lines (`line-clamp-2`), not cut to one.
- Every literal `placeholder=` under `app/` and `components/` (outside the excluded kinds above) is rewritten as "Ví dụ: …" with a real example, e.g. "Tên hoặc mã…" → "Ví dụ: Trứng gà", "Ghi chú thêm..." → "Ví dụ: giao buổi sáng", "Không bắt buộc" → "Ví dụ: …" plus the Field's "(không bắt buộc)" hint where it was the only sign.
